# 畫面設計結果

做階段一前端時,對照這份文件和 `docs/architecture.md` 第 7 章(畫面清單)。

- **設計稿**(私人連結,只有擁有者能開):https://claude.ai/artifact/UxWwBEPKvtCvrnSBppAj8z
- 設計稿裡共用的樣式檔叫 `chat.css`,**目前不在這個 repo 裡**。下面的色票、尺寸和元件規則就是從它整理來的,實作時以這份文件為準。
- 設計稿是靜態示意,沒有互動邏輯。所有行為以架構文件第 7 章為準。

## 1. 風格

手機優先,安靜的深綠青色調。亮色和暗色兩套,**自動跟隨系統設定**(`prefers-color-scheme`),沒有切換按鈕。介面只有繁體中文。

- 字體:**Noto Sans TC**(Google Fonts,字重 400、500、700、800),後備字體 `system-ui`、`PingFang TC`、`Microsoft JhengHei`。
- 自己的訊息:深青色泡泡,靠右。別人的訊息:白色(暗色是深灰綠)泡泡,靠左。
- 圖示一律用內嵌的線條 SVG(stroke 2px、圓角端點),不用 emoji 當圖示。裝飾用的圖示加 `aria-hidden="true"`。

每個代號依名稱**固定對應**其中一色(同名永遠同色,見 `nicknameColor.ts`)。做法:把代號轉成數字,除以 8 取餘數。

### 第 7 張的四個狀態

1. **載入歷史訊息**:骨架方塊加「載入訊息中…」。
2. **還沒有任何訊息**:「還沒有人說話」「來說第一句吧」。
3. **聊天室暫時無法使用**:「聊天室暫時無法使用」「請稍後再試」加「重新整理」按鈕(對應架構文件 9.4 的免費方案上限或專案被暫停)。
4. **進入畫面的其他錯誤**:代號為保留字時「這個名稱不能使用,請換一個」;連線失敗時「連線失敗,請稍後再試」。

## 5. 元件規則

**訊息**
- 別人的訊息:上方一行小字,代號(粗體、用代號色)加時間(`--muted`、只有時和分,如 `09:02`)。自己的訊息只顯示時間,不顯示代號。
- 內容換行保留(`white-space: pre-line`),長字串可斷行(`overflow-wrap: anywhere`)。
- 網址連結:`--accent` 色、加底線、新分頁開啟。自己的泡泡裡連結沿用泡泡文字色。
- 系統提示行(加入/離開):置中、灰色小字(`--muted`、約 12.5px),不是泡泡。
- 日期分隔線:中間文字、兩側一條細線。

**在線名單**
- 每人一列,高度至少 44px,左邊圓形頭像(34px,顯示代號的第一個字,底色為代號色),右邊代號。
- 自己的代號後面接「(你)」,用 `--muted`、字重 400。
- 在線小圓點用 `--ok`;斷線時改成 `--muted`。

**輸入區**
- 多行輸入框(`textarea`),預設一行高,最多長到約 120px。
- 提示列:左邊放提示文字(超速、斷線、按鍵說明),右邊放「N / 500」。超速時提示文字用 `--warn`。
- 送出鈕 44×44px。內容去掉空白後為空,或目前斷線時停用(底色 `--surface2`)。

**按鈕**
- 主按鈕:高度 52px、滿版、`--accent` 底。停用時 `--surface2` 底、`--muted` 字。
- 次要按鈕(名單、離開、重新整理、關閉):高度至少 44px、透明底、`--line` 邊框。

## 6. 實作時別忘的

- 聊天訊息區要有 `role="log"` 和 `aria-live="polite"`,新訊息才會被螢幕閱讀器朗讀。
- 只有圖示的按鈕要有 `aria-label`(例如「離開聊天室」「關閉名單」「送出」)。
- 錯誤提示用 `role="alert"`,載入和斷線提示用 `role="status"`。
- 設計稿裡訊息和名單的內容都是示範用的假資料,階段一的模擬機器人代號和對話要另外準備。
- 設計稿為了好比較,把暗色放在部分畫面。實際上亮暗色只由系統設定決定,每個畫面兩種都要能顯示。
- 設計稿裡電腦版標題旁「← 在背景分頁時,分頁標題顯示未讀數」只是設計說明,不要做進畫面。
